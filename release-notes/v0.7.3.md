# EchoFlow Code v0.7.3

本次更新主线是 **EchoFlow SiHub 浏览器登录**——不用再提前生成系统访问令牌、手工粘用户 ID，点一下登录，在弹出的浏览器窗口里用站点会话直接接管。同时带来 **执行引擎接入层落地**（引擎无关的运行时契约 + DeepSeek Harness 执行缝）、**开发质量门禁收紧**、**下载链路与站点入口修复**，以及一批文档契约上的整理。

## EchoFlow SiHub 登录

- **浏览器登录取代手工绑定**：此前要先去控制台生成系统访问令牌，再把用户 ID 与令牌手工粘进面板；用户 ID 抄错、令牌过期是最常见的两个失败原因。现在点「登录 EchoFlow SiHub」会弹出浏览器窗口，在窗口里完成站点登录即可，成功后窗口自动关闭、账户信息回填面板。**不再需要提前生成系统访问令牌。**
- **手动绑定收进折叠区**：浏览器登录走不通时点「登录未完成」提示里的展开项，仍可手工填写用户 ID 与令牌。入口文案改为「手动绑定（高级）」，文档同样记为兜底路径，不再是主流程。
- **两条线路各自独立登录**：主站与专线仍然各自登录、凭据互不覆盖，可以各登一个账号再分别建渠道。此前两条线路共用一个登录窗口，现在各自弹自己的窗口，登录窗口本身也改由线路配置驱动。
- **服务按「EchoFlow SiHub 推荐接入」呈现**：模型列表条目、服务商名称、关于页的官网链接一并改名，宣传文案从「官方一站式接入」改为「推荐接入」，不再当成官方厂商 API。新增一条合规提示并五种语言齐备：模型与服务仅在您所在地区法律法规允许的范围内提供，请自行确认所在地的合规要求与可用性。
- **账户入口从侧栏移进「设置 → 模型配置」**：侧栏原有的登录 / 退出 / 刷新余额那一组入口取消，绑定区域并入模型管理；选好线路页签即可登录、刷新或解绑，解绑只清当前选中线路的账户与本机登录状态，另一条线路不受影响。
- **主站会话凭据可直接读账户与令牌**：登录窗口交回的是站点会话，服务端据此直接读账户与令牌，不必再单独换一次令牌。
- **旧的手工绑定账户自动升级**：账户存储带了版本号，此前用系统访问令牌绑定的账户读取时自动迁移到新结构，不必重新绑定一次。
- **修复绑定按钮上显示的是占位符原文**：按钮文案此前写成 `{{endpoint}}`，插值只认单花括号，于是按钮上直接印出 `{{endpoint}}` 三个字符而不是「主站」或「专线」。
- **五种语言一并改齐**：简体中文、繁体中文、英语、日语、韩语都换到新文案。

## 登出与凭据失效

- **登出真正断干净**：此前登出只清 Cookie，登录分区的页面存储里还留着令牌，被登出的账号可能在你毫无操作的情况下悄悄登回来。现在登出与被站点拒绝的凭据都会一并清掉页面存储。
- **凭据被拒后直接给重新登录**：此前会继续走一条永远刷不出来的刷新，提示还叫你去更新系统访问令牌——可你走的是浏览器登录，手上根本没有那枚令牌。现在丢弃被拒凭据、重新读账户，界面直接给「登录」按钮；刷新失败的文案也改成叫你重新登录或换凭据。
- **本地桥一时无响应不再误判成拒绝**：此前登录窗口遇到本地服务短暂无响应就直接关掉，看起来像登录被拒。现在这种情况按「等待」处理，窗口留着；真被拒绝才清掉陈旧凭据再关。
- **站点登录页空白时自动重载一次**：站点资源加载完却不绘制时，窗口会一直白屏到登录超时。现在桌面端检测到空白就重载一次。
- **余额为负也能正常读**：站点返回负额度（欠费）时账户会话此前读不出来，现在能正常显示。
- **去掉重复的站点会话接口**：账户存储本来就已经持有凭据和读取路径，另一条平行的站点会话路由只是重复它，两边迟早走岔。

## 下载与站点入口

- **页头下载按钮此前指向文档起始页**，不是下载页。现在进下载页。
- **落地页选的系统会带进下载页**：页面底部「下载 macOS 版 / Windows 版 / Linux 版」此前只跳到下载页，选了什么不带过去，到了还要再选一次。现在选择通过地址参数带进下载页并作为初始选项；显式且合法的选择优先，没带或带了不认识的就退回按浏览器 UA 推断。
- **自定义域名缺下载元数据时不再整条链路失效**：自定义域名是独立构建的，产物里可能没有 CI 写进 `dist` 的下载清单。现在同源清单缺失时回退到 Pages 上那份完整产物做只读副本，下载照常。
- **关于页保留手动下载**：自动更新不可用时仍有手动下载入口。

## 执行引擎接入层

这一节是底层就位，**产品面还没有接上来**，现在不影响你的使用。

- **引擎无关的运行时契约**：一层介于产品与任意执行引擎之间的契约——统一事件模型、能力协商（不认识的能力一律按不支持处理）、每个连接一个 ACP 驱动，以及负责安装、会话与审批路由的 RuntimeHost。产品代码不直接引用引擎协议类型，引擎数据只走 `native` 通道。
- **DeepSeek Harness 执行缝**：`harness/` 目录持有到 DeepSeek Harness（dsh）的接缝。dsh 是执行运行时，EchoFlow 保留自己的产品外壳、界面、会话存储与 Provider 路由。**dsh 以固定版本的 npm 包接入，不打包任何 dsh 源码**，这个目录下每一行都是 EchoFlow 自己的代码。
- **自带 `echoflow` 配置档**：拒绝遥测与未列名的出站请求，并带上 EchoFlow 自有的 `egress-guard` 插件（dsh 本身不带）。目前只在测试里跑通一次握手、一个会话和一次回环提示。
- **`harness/` 自成一条检查道**：用 npm 与 Node 工具链，与根目录的 bun 树互不干扰，根目录 `bun install` 不会伸进这个目录。改动落在 `harness/` 下只跑 `bun run check:harness`。

## 开发质量与门禁

这一节是仓库的开发流程改动，面向贡献者与 Agent 会话。

- **Agent 会话质量闸门**：此前一个会话改了代码就可以收尾，没有任何机制确认跑过测试、或者有第二个上下文看过。现在钩子会记录本会话的编辑、完成的验证运行和独立子 Agent 评审，Stop 时缺口没补上就不让结束，直到补齐或维护者给出豁免。
- **闸门状态改为只追加的事件日志**：钩子是各自独立的进程，一批工具调用并发时会同时写状态，读-改-写会丢记录——而丢掉一条编辑记录，正是让未评审的改动溜过去的那一种失败。现在按会话写 JSONL 事件日志，读取时归约；旧的单文件快照首次追加时自动迁过来。
- **命令分类器按信任边界做**：假阳性是「把没跑过的验证记成跑了」，会直接放行没有证据的改动；假阴性只是多问你一次。所以一律偏向不算——heredoc 整段拒绝、引号里的不切分、`bun test-utils.ts` 这种词前缀不算 `bun test`、`&& bun test` 这种什么都没执行的语法错误不算。失败的运行照样算数：闸门问的是「跑没跑」，不是「过没过」，否则预存红测试会把会话永久卡死。
- **门禁路由与证据收紧**：路径到检查领域的映射此前在变更策略和 PR 分诊里各存一份，已经互相走岔。现在共用一份来源，PR 分诊只从基础版本读它、绝不执行 PR 代码。另外：harness 审计在缺契约检查时不再放过；适配器的缺测信号限定到改动的那个包；0/0 覆盖报成「不可用」而不是满分；根目录测试被自动发现；`AGENTS.md` 压在 24 KiB 内。
- **根目录测试预载恢复并加保护**：此前预载会被清空而不报错，恢复并加上防空断言。
- **根目录测试配置归策略检查道**。

## 文档与契约

- **指南只讲怎么拿到检查清单，不复制清单**：三处文档各存一份「表面 → 命令」表，已经互相打架（`CONTRIBUTING.md` 那份漏了 `check:mobile`），下一次加检查就会再岔一次。现在统一改成跑 `bun run check:impact` 现查，命令本身只在 `package.json` 里维护。
- **内部文档分了生命周期**：长期参考、已经做完的设计材料、死掉的跳转桩混在同一棵树里，读者分不清哪一页还在描述产品。现在维护者材料进 `_internal/`，长期事实进 `internals/`，做完的归档，根目录不再堆方案文档。
- **清理已停用的流程说明与失效脚本**：一部分流程已经不再使用，说明和它调用的脚本一并删掉；其中两条仍然管用的纪律挪进 agent 指南留着。
- **指南里的工具名换成实际装了的**：四条规则指向根本不存在的东西——斜杠命令名（Superpowers 7.x 装的是 skill 不是斜杠命令）、没启用的插件、没装的浏览器工具。现在指向真实入口；临时浏览器核查按「有什么能力用什么」写，不指定单一工具，并要求在交接里写清实际走了哪条路径、没产出视觉证据就直说没有。
