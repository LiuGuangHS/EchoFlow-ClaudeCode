# EchoFlow Code v0.7.7

本次更新主线是 **把移动端收敛成一套实现、把发布链路理顺**：旧的 Android WebView 壳及其独立 APK 发版链路已移除，手机端只保留 Expo 58 原生应用；桌面发版不再强制重打手机包；首发阶段只交付 Android。同时合入了一批集成分批（文档站与下载、桌面与服务端、IM 适配器、执行引擎接入、质量工具链）、两项 H5 安全修复，以及许可证口径整理。

## 移动端：单一实现

- **旧的 Android WebView 壳退役**：`mobile/legacy-webview/` 与 `.github/workflows/release-mobile-apk.yml` 移除，不再有第二个 Android 应用入口。旧壳的 17 项用户可感知功能逐条核对后，全部已由原生 Expo 应用覆盖；桌面服务端托管的 H5 仍供手机浏览器使用，它不是 APK，也不依赖 WebView 壳。
- **旧二维码格式继续可用**：桌面生成的局域网二维码（`?serverUrl=...&h5Token=...`）仍能被解析；连接前验证、凭据写入 SecureStore、工具审批协议与同源约束都由新增的回归契约固定，防止后续重构静默丢弃。
- **有意不迁移的旧做法**：WebView 容器、依赖 Google Play 服务的 Google Code Scanner（改为本地 ML Kit 解码）、把令牌放进 URL 查询串（原生请求改走 `Authorization` 头），以及旧品牌蓝色图标与脚手架占位资源。
- **移动端门禁转绿**：`bun run check:mobile` 1349 tests / 162 files / 0 fail，包含 typecheck、lint、测试与 H5 导出。新增 `mobile/src/core/mobileParity.test.ts`（能力承接）与 `mobile/plugins/singleMobileApp.test.ts`（单一链路）两份回归契约。

## 发布与版本链

- **桌面专用改动不再重打手机包**：解除 release-please 对 `mobile/package.json` 与 `mobile/app.json` 的版本同步。这两个文件是移动端交付指纹的一部分，此前每次桌面发版都会改版本号、必然触发一次 EAS 重新构建。现在移动版本只由 `scripts/release.ts --mobile` 显式递增。
- **沿用已验证产物**：`scripts/mobile-release.ts` 对比该平台上一次成功交付的输入摘要；摘要不变时 Android 把上次已验签的 APK 挂到新 Release（不触碰 EAS），iOS 直接跳过；摘要变了但移动版本没递增会阻止发布并提示先 bump 版本。
- **解开版本死结**：移除长期固定的 `release-as`，本版由提交中的一次性版本声明选择 `0.7.7`，后续恢复常规 patch 递增；保留 tag 与发布提交一致性校验。
- **减少通知**：PR 自动分流报告改为 GitHub Actions 摘要，不再创建或更新机器人评论；自动标签和质量检查保持不变。
- **首发只发 Android**：`release-mobile.yml` 新增 `MOBILE_RELEASE_PLATFORM` 变量，设为 `android` 后自动交付只走 Android；手动触发也可直接选 `platform=android`。Android 产物是正式签名 APK，不提交 Google Play；iOS、TestFlight 与 App Store Connect 相关配置本版不需要。

## 集成分批合入

- **文档站与下载**：SEO 与 AI 可读文档改进、下载清单与发布摘要、许可证声明恢复与根目录许可证范围的精确说明。
- **桌面与服务端**：Electron host 与桌面 UI、服务端与运行时、IM 适配器、原生 agent-desktop 源码，以及 CLI 启动器与集成工具链分批合入。
- **会话启动稳定性**：修复启动与 SDK 初始化并发更新元数据时，占位文件可能被提前删除的问题；迁移期间保留标题、附加目录快照和已有对话内容。
- **会话结束稳定性**：输入结束后等待正在进行的团队消息处理完成，再关闭输出；避免晚到提示串入后续会话，保留消息投递及正常团队关闭流程。
- **执行引擎接入**：引擎无关的运行时契约、DeepSeek Harness 执行缝、Node Host 会话门面与 `claude-agent-sdk` 驱动探针。`harness/` 仍是独立检查道，产品面尚未接上。
- **安全**：禁用 H5 访问时撤销已建立的访问；阻断远端对 EchoFlow 的变更请求。
- **质量门禁**：发布工作流与测试加固、全部 workflow 的 YAML 解析校验、移动版本独立测试、文档契约检查收紧。

## 签名与交付状态

- **macOS 采用未签名分发模式**：不包含 Developer ID 签名与 Apple 公证，系统可能提示或阻止安装、启动。当前 Computer Use 不可用，因为未签名 / ad-hoc 包无法满足现有原生组件验签要求；不放宽这些安全检查。本版 macOS 需要手动下载安装更新，不发布其自动更新 channel metadata。仍保留显式 signed 发布模式，启用时必须通过原有签名、公证与启动策略检查。
- **Windows**：未启用 SignPath 时仍交付未签名安装包，可能出现 SmartScreen 提示；不因此改变现有自动更新策略。
- **Android**：已配置部分交付凭据，但账号、项目、keystore 与云端构建的完整首发链路仍需验证；不能以 Secrets 名称存在代替实际签名与交付证据。iOS 本版不交付。

以上是本版交付方式与限制，不代表最终安装包已经构建或验收通过。
