# EchoFlow Code v0.7.2

本次更新聚焦 **运行时选择真正落到每一处执行路径**——定时任务、Team 成员、会话切换失败提示都跟上你选定的 CLI；运行时页面把「检查过什么、什么时候检查、文件在哪」讲清楚。同时带来 **EchoFlow 账户与 Provider 文案全面接入多语言**、**工具安全检查补漏**，以及一批稳定性修复。

## 运行时与定时任务

- **定时任务跟随你选定的 CLI 运行时**：此前定时任务固定按 `CLAUDE_CLI_PATH` 找可执行文件，切换到本机安装的 Claude Code 后，定时任务仍跑在自带运行时上，页面上看不出任何差别。现在定时任务与会话走同一套运行时配置；在任务里显式指定路径仍然优先。
- **定时任务配置失效时回落默认运行时**：存下的路径被删除或改名后，会话能让你重新选，但排到明天的任务不能。解析不出可用路径时按自带运行时执行，不让任务直接失败。
- **Team 成员继承队长的 CLI 运行时**：会话切到本机安装的 Claude Code 后，成员此前仍在自带运行时上启动，等于你批准的成员跑在另一个可执行文件上。现在只继承可执行文件，Provider、模型和推理强度仍按成员各自设置。
- **运行时卡片显示所选可执行文件的路径**：「本机的 Claude Code」此前只说找到了、没说是哪个文件，选错了要到会话起不来才发现。路径只在仍然可用时显示，不会出现上面写着「可用」、下面却指向一个已消失文件的矛盾。
- **每次探测都带时间**：版本号和「已找到」是某次检查的结果，不是恒定状态。现在同一次检查的条目统一打上时间，页面显示「刚刚检查」「N 分钟前检查」或「从未检查」——没找到的条目也带时间。本地条目可以直接在文件管理器里定位（WSL 条目除外，它们的路径在另一个文件系统里）。
- **可执行文件消失后不再提供 External 运行时**：卸载或改名后，该选项此前仍可选，要到真正启动会话才失败。现在与选择时做同样的校验，路径失效即视为未安装，直到你重新指定。
- **会话切换失败时显示实际在跑的运行时**：切换失败会服务端回滚，选择器此前仍停在被拒绝的那一项上，旁边就是失败提示。现在失败提示出现时，选择器回到真正正在运行的运行时。

## 账户、Provider 与多语言

- **EchoFlow 账户与 Provider 文案全面接入多语言**：官方账户登录页此前有 24 条硬编码中文，非中文界面会夹中文。端点标签、凭据字段、账户概要全部走语言包；消息里的图片标签、Provider 设置里的凭据状态与端点标签也接上已有的语言键，五种语言一并补齐。
- **修复登录后侧栏不显示账户**：`/api/echoflow` 的请求处理拿不到上下文，一律 500，登录成功的账户永远出不来。现在三条调用路径都显式传入上下文。
- **登录身份识别兼容站点验证参数**：此前按完整字符串匹配登录回调地址，站点附加的人机验证令牌会让匹配永远不命中、登录身份读不到。改为按来源与路径匹配。
- **凭据文件创建即 0600**：此前先按默认权限创建再收紧，中间有一小段时间可被同机其他用户读到。现在一步创建为 0600。

## 工具安全

- **bash 安全检查不再放过以管道开头的命令**：续行符检查列了 `&&`、`||`、`;`、`>`、`>>`、`<`，唯独漏了 `|`，于是 `| rm -rf …` 被当成完整命令直接放行。正常位置的管道（`ls | grep x`）不受影响。
- **PowerShell `Remove-Item` 保护与 sed `w`/`e` 允许列表补齐覆盖**：补上针对这两处危险写法的测试，避免后续改动悄悄放宽。

## 稳定性与性能

- **瞬时状态提示不再在组件卸载后弹出**：几个设置页用定时器把「已复制」之类的提示改回原样，却从不清定时器，状态在测试环境拆掉之后才落地，表现为未处理异常和整条检查失败。现在定时器随组件卸载取消。
- **打开文件路径不再重复 stat**：同一次打开对同一路径查两次，去掉一次。
- **测试改为等待真实事件**：一批依赖固定等待时长的测试改成等实际发生的事件，减少「本机慢一点就红」的假失败。
- **移除 `claude-haha` 兼容入口**：该入口只是转调 `echoflow-code`，没有任何安装包、文档或发布产物依赖它。命令行统一为 `echoflow-code`。
