# DeepSeek Harness

原版 DeepSeek Harness（`@deepseek-ai/dsh`）的安装与运行已经收进桌面端，不需要自己配 Node 环境、装 npm 包、开终端。入口在侧边栏的「**DeepSeek Harness**」，点开是一个独立标签页。

## 它和 EchoFlow 的关系

这一节要放在最前，因为它决定了你会怎么用它。

**DeepSeek Harness 的数据完全独立，两边互不干扰。** 它有自己的配置目录、会话和插件，**不会**与 EchoFlow 的服务商、会话、Skills、MCP 或 Agents 自动同步。你在 EchoFlow 里配好的模型渠道，Harness 那边看不到；反过来也一样。

**它也不接入 EchoFlow 的 Agent Loop。** Harness 的会话与插件能力保持独立。所以别指望"在 Harness 里做的事"会出现在 EchoFlow 的会话记录里，或者被 EchoFlow 的子 Agent 复用。

当前阶段**不提供插件市场**，插件管理能力会单独设计。

一句话：**它更像一个开在应用里的独立工具窗口，而不是 EchoFlow 的一个功能模块。**

## 一键安装

面板首次打开时状态是「未安装」，中间只有一颗「安装 DeepSeek Harness」按钮。点它即可，Node 运行环境和 Harness 包都由桌面端统一管理。

如果按钮显示的是「**安装运行环境并安装 DeepSeek Harness**」，说明本机缺一个可用的 Node 运行时，点下去会先把运行环境准备好，再装 Harness。见下一节。

## 运行环境要求

内置运行时要求 **Node.js 22.19.0 及以上**。

从 0.5.6 起，不满足时应用会**自动下载最新兼容的 LTS 版本**，校验 SHA-256 之后再切换过去，安装失败会**自动回滚**。整个过程在面板里能看到进度，中途不需要你介入。

如果自动准备也失败，面板会明确报「**运行环境不可用**」，而不是静默失败——这种情况下看面板上的错误提示，或者去 [装不上 / 打不开 / 连不上](../start/troubleshooting.md) 查。

## 生命周期控制

装好之后，面板上的按钮会随状态变化：

| 状态 | 能做什么 |
|---|---|
| 未安装 | 安装（或先装运行环境） |
| 已停止 | 启动 · 更新 / 重新安装 |
| 正在运行 | 打开 DeepSeek Harness · 重启 · 停止 |

「打开 DeepSeek Harness」进去的是**原版界面**，不是 EchoFlow 包装过的版本。

端口按需自动分配，不用你指定；启动带超时保护，卡住时不会无限等待。

## 状态与版本

面板右上角的状态徽标是你最该看的东西：

- **正在运行** — 服务已起来
- **正在安装运行环境** — 在准备 Node，等着就行
- **运行环境不可用** — Node 版本不满足或准备失败
- **已停止** — 装了没启动
- **未安装** — 还没装

装了之后，面板上会显示「当前版本：x.y.z」。

**出错了就地提示**，不需要去翻日志文件。

## 更新与重装

点「**更新 / 重新安装**」会重新拉一次 Harness 包，升到最新版；装坏了也可以用它修回来。这个动作不影响 Harness 自己的数据目录。

## 常见问题

**报「运行环境不可用」。** 需要 Node.js 22.19.0+。0.5.6 起会自动下载兼容的 LTS 并校验，失败会回滚；仍在旧版本上就先升级应用。

**启动超时。** 端口按需分配、启动有超时保护，通常是被别的东西占住了端口或首次启动较慢。等一会儿重试，或者「重启」一次。

**在 EchoFlow 里配的模型，Harness 里怎么没有。** 这是设计如此。两边数据独立，Harness 的模型和插件要在它自己的界面里配。

**Harness 的会话会出现在 EchoFlow 的会话列表里吗。** 不会。它有自己的会话存储，也不接入 Agent Loop。

**移动端能用吗。** 不能。这个入口只在桌面端运行时可用的前提下出现。
