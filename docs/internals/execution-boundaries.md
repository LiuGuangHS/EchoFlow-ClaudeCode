# 执行、数据与信任边界

这份规范划清一次会话从输入、执行、持久化到对外发送的责任。它规定实现和评审必须守住的边界，不代表所有路径已经通过验证，也不授权启动运行时迁移。当前架构见[架构总览](./index.md)，检查流程见[参与贡献与质量门禁](./contributing.md)。

## 先记住四条规则

1. **EchoFlow 产品能力独立于执行引擎。** 项目、工作区、会话管理、任务、Agent Teams、计划任务、记忆、扩展、通知和 IM 接入属于产品层。更换或增加引擎不能删掉这些能力，也不能让引擎成为第二个产品入口。
2. **一次操作只有一个执行 owner。** 提交前选择执行绑定；被接受、消费或消费状态不确定后，不得自动换引擎重放。失败要留下可诊断状态和人工处理入口，不把“重试成功”冒充 exactly-once（恰好执行一次）。
3. **每类源数据都有明确的权威归属。** 会话、审批、归档和附件各自需要写入与协调契约，不能有两个互不了解的 writer 同时宣称权威。这不要求所有记录由同一个进程写入。缓存、索引和 UI 状态是投影，不能据此恢复已删除的源数据。
4. **边界要在真实入口验证。** 单元测试证明解析和局部逻辑；跨进程、平台回调、文件外发和 Electron 导航需要真实入口或隔离 loopback（本机回环）fixture，不能只 mock 被测模块。

## 所有权模型

| 对象 | 责任边界 | 不允许的替代方案 |
| --- | --- | --- |
| 产品能力 | EchoFlow 的 Server、桌面端和 adapters 编排产品功能 | 用某个 Agent SDK 或 CLI 的默认行为替代产品功能 |
| Agent 回合 | 当前 CLI/Agent core 执行工具、权限、压缩、子 Agent 和回合恢复 | 在 Server、adapter 或另一个 sidecar 再实现一套回合循环 |
| 会话源数据 | 沿用 transcript 与元数据各自的持久化契约；索引和列表是可重建投影 | 没有明确归属契约便在 legacy JSONL 之外增加第二份权威 transcript |
| 执行绑定 | 提交前确定执行引擎、进程和所需能力；已接收操作不得隐式换 owner | 已送达后自动换引擎、双跑有副作用的工具、无条件重放 |
| 审批决定 | 请求 owner 保存 pending 状态；已认证的平台 envelope 提供 actor 身份 | 从卡片字段、聊天文本或客户端传入的 `userId` 推断身份 |

执行绑定规则不禁止按既有协议在后续回合调整模型配置。引入原生模块前，必须定义它与 Server、CLI core 和持久化 owner 的边界，再提供协议、恢复和真实进程重启证据；替换一个 sidecar 不等于迁移完成。

## 信任边界

### 文件和图片外发

Agent 输出不能直接作为可信附件。应复用 `adapters/common/attachment/outbound-image.ts` 的安全加载边界：

- 会话必须有明确工作目录；
- 文件路径和工作目录都经 `realpath` 解析，目标仍在工作目录内，且为普通文件；
- 文件和内联图片都受现有大小上限与 MIME 白名单约束；内联数据不适用文件路径检查；
- Agent 输出的远程 URL 不由本地发送路径自动抓取。

平台专用 API 负责上传已验证的字节，不能重新定义路径、大小或远程地址策略。

### 平台审批回调

卡片内容和客户端参数不是身份凭据。处理审批时从已认证的平台 envelope 取得 actor，并核对：

- request ID 仍是 pending；
- actor 是预期接收者，并且当前仍获授权；
- 卡片或回调实例与该请求匹配；
- 允许一次、永久允许和拒绝都经过同一套授权检查。

缺失、伪造、过期或不匹配的回调不得改变 pending 状态。业务路由使用服务端保存的请求上下文，不使用客户端提供的 `chatId`。

### Electron 导航

拥有文件、终端、会话和 IPC 权限的窗口只能导航到配置的开发 origin 或打包 renderer 的精确入口，包括合法 hash 路由。其他 `file:`、其他 loopback origin 和外部页面不得继承主窗口权限；HTTP/HTTPS 外链交给系统浏览器。

在 `will-navigate`、主框架 `will-redirect` 和新窗口入口分别验证这条规则。预览和子框架内容不得通过这些入口把自己提升为受信任 renderer；仅通过顶层导航测试不代表已经证明子框架隔离。

### 文档发布

`docs/_internal/` 是维护者资料，不是公开文档。生成 manifest、content modules、search index、静态路由和 sitemap 时必须在扫描阶段排除它，不能仅靠“不在导航里”隐藏。公开中英文页面保持对应；内部目录同样不能存放凭据或真实用户状态。

## 持久化和删除

### 迁移

持久化 JSON、localStorage、app config 或 session metadata 的格式变化必须：

1. 提供旧格式的前向迁移；
2. 保留未知字段和未涉及的设置；
3. 用旧 fixture 覆盖真实启动读取顺序；
4. 通过 `bun run check:persistence-upgrade`。

无法理解的未来版本必须保持原样并停止写回。不能先加载成默认值，再由 debounce、`pagehide` 或 `dispose` 覆盖未来数据。

### 写入失败

写入队列要保留目标文件身份，避免把旧数据写进被替换的文件。打开、追加、关闭或后续 flush 失败时：

- 已确认写入的字节不能盲目重放；
- 结果不确定的追加不能靠 truncate 删除并发 writer 的字节；
- 尚未提交且仍属于原文件的条目要能被后续 flush 发现；
- 后台 timer 失败必须可观察，并清理 drain 状态，不能留下未处理 rejection 或永久卡住的队列。

这不是 exactly-once 承诺。应保留可诊断的未确认状态，而不是把不确定的副作用当成安全重试。

### 删除和归档

单删和批删应有一致的删除结果；清空 transcript 与删除会话是不同操作，保留各自的用户语义，但共享以下安全约束：

- 在适用的 archive lock 内跨进程重新检查保护状态；
- 明确 transcript、tool results、subagent transcript 和 archive metadata 的归属及处理范围；
- retention cleanup 尊重归档保留意图；用户明确删除时，按删除契约处理归档元数据，不能让旧索引或归档记录重建会话；
- 延迟写入不能重建已删除会话，也不能把清空前的内容写回；
- 不触及其他会话、工作区或仍在使用的无关文件。

归档是保留决策，不是第二份 transcript。archive state 损坏或版本未知时，停止破坏性清理并报告错误。

## 验证与交接

测试设计和命令以[参与贡献与质量门禁](./contributing.md#回归测试设计)为准。边界修复至少提供以下证据：

| 风险 | 所需证据 |
| --- | --- |
| 迁移和启动读取 | 旧 fixture、未知字段、未来版本，以及真实读取顺序 |
| 审批和 adapter 路由 | 实际入口配合 mock transport，覆盖允许、拒绝、重复和过期路径 |
| 文件外发和并发写入 | 临时目录、真实路径/文件身份、故障注入；跨进程声明需要多进程证据 |
| Electron host 和导航 | 主进程测试及隔离桌面/browser smoke；renderer unit test 不能替代 |
| 恢复和删除 | 失败、重复、晚到事件和重启后状态；同进程恢复不能替代真实进程重启 |

记录每项检查的 `passed`、`failed`、`blocked`、`skipped` 或 `not run`。mock、构建成功、真实浏览器、真实平台回调和 live provider 是不同证据；缺少哪层就明确记录，不能用旧报告覆盖当前失败。真实模型或平台检查仍需明确授权，发现本机凭据不构成授权。

## 明确不做的事

- 不建立第二个 RuntimeHost、冲突的 session writer 或用全局 cwd/env 临时切换充当并发隔离；
- 不通过每应用 allowlist、denylist 或权限等级改变 Computer Use 的全应用统一授权边界；
- 不把内部设计稿、真实用户配置、token、QR code、provider key 或本机路径写进公开文档；
- 不降低 coverage baseline、放宽断言或重复失败直到偶然通过来掩盖问题。

源码入口规则以根目录及各目录的 `AGENTS.md` 为准；这份页面保存跨目录的长期不变量，不代替实现与验证记录。
