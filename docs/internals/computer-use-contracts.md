# Computer Use 协议与验证

Computer Use 的工具注册、运行组件就绪、输入投递与目标实际完成是不同状态。本页解释协议和验证方法，不是已通过的验收清单，也不把历史设计或实验当成已实现能力。平台支持、授权入口、会话与分发见 [Computer Use 架构](computer-use.md)。

## JavaScript 与原生边界

| 边界 | 负责内容 |
| --- | --- |
| TypeScript 宿主 | 平台可用性、全局启用状态、会话锁、取消与原生通道 |
| macOS Swift helper | 进程和窗口校验、AX 树与动作、定向输入、截图 |
| 操作系统 | 辅助功能、屏幕录制、应用焦点与图形会话 |

macOS 的持久 JavaScript 会话通过 `cua.getApp()` 绑定目标，由宿主转发原生调用。入口是 `src/utils/computerUse/replRuntime.ts`、`replWorker.ts`、`replCompiler.ts` 和 `src/vendor/computer-use-mcp/replApi.ts`；原生实现位于 `native/cu-helper/Sources/cu-helper/`。脚本中的 App 对象不能绕过全局授权、进程身份、窗口校验或取消。

Windows/Linux 使用独立的 agent-desktop 引擎，不套用 Swift helper 的输入机制。原生 App 输入与浏览器 Tab/DOM 自动化也是不同链路；给浏览器发送原生坐标事件，不代表获得了 DOM 节点或 Playwright 能力。

## 权限与签名

设置中启用并确认一次 consent，即授权所有受支持应用；不增加逐应用审批、应用名单或权限分层。全局禁用、系统权限和目标有效性检查仍然生效。完整的配置保留与数据边界见[主概览](computer-use.md#一个全局应用授权入口)。

macOS 辅助功能与屏幕录制是不同权限。安装包、宿主和 helper 的签名与启动方式会影响系统对权限主体的识别。开发二进制运行成功不能代替安装版授权、更新后权限保留和打包链路验证。unsigned/ad-hoc 分发包不能通过现有 helper 验签，Computer Use 不可用，且需要手动更新；不能把这种包的构建成功当成 CU 验收，详见[构建与分发](computer-use.md#构建与分发)。

## 观察、元素与窗口

AX 树提供控件语义，窗口截图提供可见上下文；二者必须绑定同一进程、窗口和坐标关系，不能仅凭相似标题匹配。一次截图不证明后续界面没有变化：元素句柄需要世代与活体校验，图像需要捕获新鲜度判断。macOS AX 句柄带有世代；陈旧引用应重新观察，而不是猜测当前位置。

自绘界面可能不提供完整 AX 树，坐标路径仍需要窗口身份和有效截图。缺少 AX 节点不等于应用完全不可操作；存在节点也不保证支持所需动作。截图缩放坐标、窗口逻辑坐标和全局坐标必须使用一致转换，包括多屏与 Retina 缩放。

Chromium、CEF 与 Electron 的输入路由还依赖窗口身份，仅有 PID 与屏幕坐标不足以证明控件接收了输入。`WindowTargetedEvent.swift` 负责窗口事件构造，`Injection.swift` 负责投递；`AXAction.swift`、`WindowGeometry.swift` 与 `MouseDragEventTests` 涉及动作、坐标和拖拽事件顺序。事件工厂必须保持窗口绑定与事件顺序一致，但构造正确不等于目标应用接受输入。

## 动作、焦点与视觉反馈

已确定的动作可以在同一脚本内顺序执行，新的决策点再显式读取 AX 状态或截图，不必把每次输入都变成一次模型往返。图像输出、文本输出与原生状态刷新是不同事实；菜单、窗口或界面结构变化后，应重新建立观察基线，不能继续使用失效引用。

动作回执、事件投递和目标实际完成也不同。批量执行不是事务；超时、取消、脚本失败或部分投递不会回滚已发生的副作用。先观察现状再决定是否继续，不自动重放，也不静默切换到另一条执行链重试。

窗口路由不能替代焦点、进程生命周期和真人干预检查。macOS 不移动真实指针的 AX 操作与定向输入，不代表独立桌面，也不是 Windows/Linux 的通用承诺；图形会话、焦点和剪贴板仍是共享资源，同一应用内的真人操作可能干扰结果。

虚拟光标是视觉反馈，不是第二套硬件鼠标或独立桌面。隐藏、遮挡、多屏与 Space 切换会影响反馈可见性，光标动画结束不能证明输入交付。被遮挡、隐藏、最小化或位于其他 Space 的目标，需要分别判断捕获新鲜度与输入可达性；不能把缓存画面或一次投递当成完成证据。

## 确定性回归与真机证据

临时配置、fake runner、模拟原生工具和 loopback transport 可验证参数、会话身份、全局启用状态、错误、取消、清理与 worker 隔离。跨进程测试同样使用可丢弃目录，不得读取真实用户 home、provider、令牌或桌面数据。真实模型和真实桌面操作是独立证据，不混入常规确定性门禁。

| 证据 | 可以说明 | 不能代替 |
| --- | --- | --- |
| schema、参数与模拟传输测试 | 接口校验、错误和取消传播 | 真实桌面输入 |
| 原生事件工厂测试 | 事件顺序、窗口和坐标字段 | 操作系统或目标应用接收与完成 |
| 指定应用的真机观察 | 该版本、环境和步骤的行为 | 所有应用或模型任务成功率 |
| 模型任务记录 | 该任务中实际走过的调用链 | 未执行功能的兼容性 |

兼容性结论需要注明接口或客户端版本、平台与目标应用、参数和返回结构、进程与窗口绑定、输入路径和实际界面变化。不能用工具名称相似、一次任务成功或完成度百分比代替这些证据；一条原生或 DOM 路径的结果也不能证明另一条。二进制导入表或字符串中缺少某个符号，不能单独证明没有动态调用该能力。

### 需要单独观察的边界

| 范围 | 需要记录的证据 |
| --- | --- |
| macOS 安装版授权 | 辅助功能、屏幕录制、签名身份、重建或更新后的授权状态 |
| 目标与焦点 | 前后台实际进程、窗口身份、真人输入和真实指针是否受影响 |
| CEF/Electron | 目标窗口是否真正收到点击和文本，而非只返回动作成功 |
| 多屏与遮挡 | 坐标换算、截图范围、光标反馈的可见位置 |
| 全屏与其他 Space | 是否抢前台或切换桌面、截图新鲜度、拒绝原因 |
| 最小化与隐藏 | 观察与动作是否恢复窗口、是否激活目标、何时要求重读 |
| 全屏叠加最小化或隐藏 | 看不见的目标是否被明确拒绝，而不是误报完成 |
| Windows/Linux | 原生能力、物理输入副作用、图形会话和平台限制 |

这些是待验证维度，不是跨 Space、隐藏或最小化窗口可操作性的承诺。每次结论还要注明应用与系统版本、窗口初态、操作步骤及目标界面前后变化。macOS 构建或 mock 不能代替 Windows/Linux 输入证据。

### 不把回执当结果

同一目标应用只由一个实验者操作，使用唯一标记区分输入，避免把其他 Agent 或真人的修改当成成功。超时、取消或部分投递后先重新观察，不重复可能已经发生的副作用。

发布或回归报告应分别列出 passed、failed、skipped、blocked 和 not run；构建、模拟测试与真机结果不能互相替代。本页不声明新的硬件验证结果。

## 失败与性能也属于契约

陈旧句柄、歧义目标、失去权限、进程退出、超时、部分投递与取消都需要准确的失败语义。性能优化不能删掉进程身份、焦点确认、取消或释放按键等保护，也不能通过自动重放副作用提高表面成功率。

性能记录应拆开模型往返、动作次数、观察次数、AX 遍历、截图、输入、工具耗时和目标实际完成的耗时。含长时间空闲的会话总时长不能推导单次输入延迟，其他引擎的轨迹不能作为本实现的基准，一个应用实验中的固定等待也不是所有应用的规格。
