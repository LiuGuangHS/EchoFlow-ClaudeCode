# Computer Use 观察与执行分层

Computer Use 的核心不是反复截整屏再猜坐标，而是让观察、定位和动作绑定同一目标，同时保留各层的失败语义。本页解释分层原则；当前各平台实现见 [Computer Use 架构](computer-use.md)。

## 观察建立定位依据

AX 树提供控件语义，窗口截图提供可见上下文。二者都需要明确的进程、窗口和坐标关系；一次截图不证明后续时刻界面没有变化。元素句柄需要世代与活体校验，图像需要捕获新鲜度判断。

有些自绘界面不提供完整 AX 树，此时坐标路径仍需窗口身份和有效截图。没有 AX 节点，不等于应用完全不可操作；有 AX 节点，也不保证该控件支持所需动作。

## 执行与下一次观察分开

已确定的动作可以在同一脚本内顺序执行，新的决策点再请求观察。不要把每次输入都强制转成一次模型往返，也不要在界面已变更后继续使用失效引用。

动作回执、事件投递和目标实际完成是不同事实。失败或取消可能发生在副作用之后，不能通过自动重试掩盖结果未知。详见[原生协议契约](computer-use-codex-impl-blueprint.md)。

## 视觉反馈不是定位依据

虚拟光标用于让用户理解 Agent 正在操作的位置，不是独立桌面或真实指针的副本。窗口隐藏、遮挡、多屏和 Space 切换会影响反馈可见性，不能用光标动画结束代替输入交付证明。

## 性能优化不能删校验

衡量耗时时应分开记录模型往返、AX 遍历、截图、输入与目标界面变化。消除重复等待不能删掉进程身份、焦点确认、取消或释放按键等保护；一个应用上的固定延迟不应成为所有应用的规格。

跨平台引擎的输入机制和能力不同。macOS 的后台定向输入不能当成 Windows/Linux 的通用承诺，相关证据边界见[验证说明](computer-use-native-manual-qa.md)。
