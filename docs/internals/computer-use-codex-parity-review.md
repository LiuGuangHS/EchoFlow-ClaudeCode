# Computer Use 兼容性评估

Computer Use 的兼容性应描述具体接口、目标环境与验证范围，不能用一个完成度百分比代表所有应用的成功率。当前产品边界见 [Computer Use 架构](computer-use.md)，macOS 调用边界见[原生协议契约](computer-use-codex-impl-blueprint.md)。

## 沿实际调用链比较

一次兼容性结论至少说明：使用的接口或客户端版本、平台与目标应用、参数和返回结构、进程与窗口绑定、输入投递路径，以及实际观察到的界面变化。

原生 App 坐标输入和浏览器 Tab/DOM provider 是不同机制，不能用其中一条路径的结果证明另一条。二进制导入表或字符串中没有某个符号，也不能单独证明运行时没有动态调用该能力。

## 分开报告证据

| 证据 | 可以说明 | 不能代替 |
| --- | --- | --- |
| schema、参数与模拟传输测试 | 接口校验、错误和取消传播 | 真实桌面输入 |
| 原生事件工厂测试 | 事件顺序、窗口和坐标字段 | 目标应用接收与完成 |
| 指定应用的真机观察 | 该版本、环境和步骤的行为 | 所有应用或模型任务成功率 |
| 模型任务记录 | 该任务中实际走过的调用链 | 未执行功能的兼容性 |

## 失败与性能也属于契约

兼容不只是成功路径。陈旧句柄、歧义目标、失去权限、进程退出、超时、部分投递和取消都需要保留准确语义；不能为了提高表面成功率而放宽身份检查或自动重放副作用。

性能记录应拆开模型往返、动作次数、观察次数和工具耗时。含长时间空闲的会话总时长不能推导单次输入延迟，其他引擎的轨迹也不能当成本实现的基准。

真机验证的环境与限制见[验证边界](computer-use-native-manual-qa.md)。本页提供评估方法，不声明新的硬件验证结果。
