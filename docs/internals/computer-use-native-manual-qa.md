# Computer Use 验证边界

Computer Use 的确定性回归和真实桌面验收回答不同问题。本页说明验证范围，不是已通过的测试清单，也不声明任何平台或应用已经完成真机验证。机制与限制见 [Computer Use 架构](computer-use.md)。

## 确定性回归能证明什么

临时配置、fake runner 和 loopback transport 可验证参数、会话身份、全局启用状态、错误、取消与清理。原生事件工厂可以检查事件顺序和窗口坐标，但不能证明操作系统或目标应用接收了事件。

这些检查不得读取真实用户 home、provider、令牌或桌面数据；跨进程测试也要使用可丢弃目录。真实模型与真实桌面操作是另外的验证，不应混入常规确定性门禁。

## 需要单独观察的边界

| 范围 | 需要记录的证据 |
| --- | --- |
| macOS 安装版授权 | 辅助功能、屏幕录制、签名身份、重建或更新后的授权状态 |
| 目标与焦点 | 前后台实际进程、窗口身份、真人输入和真实指针是否受影响 |
| CEF/Electron | 目标窗口是否真正收到点击和文本，而非只返回动作成功 |
| 多屏与遮挡 | 坐标换算、截图范围、光标反馈的可见位置 |
| 全屏与其他 Space | 是否抢前台或切换桌面、截图新鲜度、拒绝原因 |
| 最小化与隐藏 | 观察与动作是否恢复窗口、是否激活目标、何时要求重读 |
| 全屏叠加最小化或隐藏 | 看不见的目标是否被明确拒绝，而不是误报完成 |
| Windows/Linux | 原生能力、物理输入副作用、图形会话和平台限制 |

这些是待验证维度，不是对跨 Space、隐藏或最小化窗口可操作性的承诺。每次结论要注明应用与系统版本、窗口初态、操作步骤及目标界面前后变化。

## 不把回执当结果

同一目标应用只由一个实验者操作，使用唯一标记区分输入，避免把其他 Agent 或真人的修改当成成功。超时、取消或部分投递后先重新观察，不重复可能已经发生的副作用。

发布或回归报告应分别列出 passed、failed、blocked 和 not run；构建、模拟测试与真机结果不能互相替代。协议层的检查项见[兼容性评估](computer-use-codex-parity-review.md)。
