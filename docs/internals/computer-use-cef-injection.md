# CEF 与 Electron 窗口输入

macOS 向目标进程投递事件时，还需要把事件绑定到正确的窗口。Chromium、CEF 与 Electron 的输入路由依赖窗口信息；仅有目标 PID 和屏幕坐标，不足以证明目标控件收到了输入。平台总览见 [Computer Use 架构](computer-use.md)。

## 进程、窗口与坐标是一条链

`native/cu-helper/Sources/cu-helper/WindowTargetedEvent.swift` 负责构造窗口定向事件，`Injection.swift` 负责输入投递。鼠标事件通过 AppKit 构造后取得 CGEvent，保留目标窗口身份、全局位置和窗口内位置，再通过 `postToPid` 发送。

- 截图与输入必须绑定同一目标进程和窗口，不能只凭相似标题匹配。
- 截图缩放坐标、窗口逻辑坐标和全局坐标需要统一转换；多屏与 Retina 缩放不能各算一套比例。
- AX 语义动作与坐标事件是不同路径。控件没有暴露 AX 动作，不意味着坐标输入一定成功。

## 焦点与回执的限制

窗口路由不能代替焦点、进程生命周期和真人干预检查。后台输入也不等于独立桌面：目标应用可能改变焦点，剪贴板仍是系统共享资源。不要把旧实验中的固定等待时长当成所有应用通用的契约。

事件构造成功或动作回执成功，不等于目标界面已经完成变化。应在下一个决策点重新观察窗口状态；超时、取消或部分投递后先确认现状，不盲目重发点击、粘贴等副作用。

## 验证入口

事件工厂的确定性测试可以检查窗口绑定、坐标和事件顺序，但不能证明所有 CEF/Electron 版本都接受输入。实际目标的前后台交互、多屏、隐藏和最小化行为需要单独的真机证据，见[验证边界](computer-use-native-manual-qa.md)。
