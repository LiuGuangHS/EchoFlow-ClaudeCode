# 移动端 App

EchoFlow 只有一个 iOS / Android App 主线：使用 Expo 与 React Native 构建的移动端 App。它连接正在运行的 EchoFlow Desktop 或本地服务，手机负责查看会话、处理审批、回答问题、派发任务和查看结果；模型执行、项目文件与桌面运行时仍由电脑负责。

手机浏览器通过 H5 入口使用同一套界面与会话协议，适合临时访问；远程访问仍需电脑端配置受限入口并完成浏览器配对。H5 不是第二个 App，不提供原生扫码、推送、SecureStore 或系统级后台活动，但可查看和操作由电脑执行的任务。

## 能力与边界

以下为当前源码支持的能力范围，不代表所有平台均已完成构建或真机验收。

| 能力 | 当前说明 |
| --- | --- |
| 多台电脑 | 每台电脑有独立地址、连接状态、凭据和草稿；保存前必须完成连接验证。 |
| 配对与连接 | 支持扫码、粘贴连接信息和手动输入；拒绝重定向和不受信任的连接地址，远程配对需要电脑端批准。 |
| 会话与审批 | 复用桌面端的会话、流式消息、断线恢复、去重、工具审批、问题和计划协议；迟到或重复的操作不会绕过当前会话校验。 |
| 文件与语音 | 支持图片、文件选择、分享和语音输入；文件大小、类型、取消和权限失败会明确反馈。 |
| 通知与后台 | 原生 App 可接入系统通知、后台活动和平台能力；电脑停止或休眠时，手机不能代替电脑执行任务。 |
| H5 | 桌面端托管 `/m/`；局域网凭据保留在当前浏览器会话内，刷新后可能需要重新连接。远程浏览器配对使用 Cookie，与原生 App 的 Bearer 凭据分离。 |
| iOS / Android | 源码和配置共用一条 Expo 构建链；正式发布、真机通知、后台活动和签名状态以对应版本的实际证据为准。 |

移动端不是桌面端的本地执行器。API Key、Provider、MCP、插件、项目文件和高风险系统设置仍以桌面端为主要管理入口；移动端收到的审批动作必须在当前电脑、会话和请求 ID 下重新校验。

## 从电脑连接

1. 在电脑上启动 EchoFlow Desktop 或本地服务。
2. 打开桌面端的手机连接 / H5 访问设置，按页面提示生成连接二维码或配对链接。
3. 确保手机能访问电脑地址。局域网使用电脑的局域网 IP；远程访问使用 HTTPS、VPN、Tailscale 或桌面端提供的受限远程入口。
4. 打开 EchoFlow App，扫描二维码，或粘贴连接信息并确认主机。
5. 连接验证成功后，进入会话列表；远程配对还需要在电脑上批准这台设备。

二维码中的 `127.0.0.1` 或 `localhost` 指向手机自身，通常不能从实体手机访问电脑。请改用电脑的局域网地址、VPN 地址或 HTTPS 域名。不要把桌面主服务端口直接暴露到公网。

丢失手机或怀疑凭据泄露时，请在电脑端撤销配对设备并轮换相关凭据。当前局域网 H5 的关闭或 Token 轮换尚不能作为所有既有连接和恢复流均已即时失效的保证；需要立即隔离时，应停止相关服务并关闭远程入口。网络中断或电脑休眠不代表任务已经完成，恢复连接后请核对会话状态。

## H5 与原生 App 的选择

| 需求 | 入口 |
| --- | --- |
| 继续完整会话、审批权限、上传材料 | EchoFlow App |
| 临时查看或在不便安装 App 的设备上操作 | 桌面端托管的 H5 (`/m/`) |
| 快速提交任务、接收提醒、轻量审批 | 已配置的 IM 适配器 |

电脑端的远程连接步骤见[桌面端远程访问](../desktop/remote.md)。移动端只说明用户操作与支持边界；开发、Expo 配置、平台差异和构建命令见仓库根目录下的 `mobile/README.md`。

## 支持状态

代码中已有的功能、通过离线测试的功能、在模拟器或真机验证的功能，以及已经发布到商店的功能不是同一件事。下载入口和可安装版本以 EchoFlow Releases 的实际产物为准；未发布的构建配置不能作为安装承诺。原生构建、通知、后台活动、相机和语音权限需要在对应平台和版本上单独验证。
