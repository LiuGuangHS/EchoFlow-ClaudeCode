# 绑定 EchoFlow 官方账户

EchoFlow Code 可以直接调用 EchoFlow 提供的模型服务。绑定账户之后，你不需要自己申请各家厂商的密钥，选一个调用令牌就能建好一条模型渠道。

如果你用的是别的服务商，看 [连接模型服务](./models.md)。这一页只讲官方账户。

## 前置条件

- 在 [EchoFlow 控制台](https://api.echoflowai.cc/console/personal) 注册过账号，并且账户里有余额
- 已经生成一枚**系统访问令牌**（控制台里的「安全设置 → 系统访问令牌 → 生成令牌」）
- 桌面端已经装好，见 [下载与安装](./install.md)

## 两条线路：主站与专线

官方服务有两个入口，绑定区域顶部是它们的切换页签：

| 线路 | 地址 | 什么时候选它 |
|---|---|---|
| **主站** | `https://api.echoflowai.cc` | 默认。多数情况下用这条 |
| **专线** | `https://expapi.echoflowai.cc` | 主站不稳或延迟偏高时换这条试试 |

**两条线路各自独立绑定，凭据互不覆盖。** 你可以在主站绑一个账号、专线上绑另一个，再分别建渠道。页签上的小圆点是绑定状态：绿色表示这条线路已经绑定。

## 绑定账户

在「设置 → 模型配置」（旧版叫「服务商」）里找到官方的绑定区域，选好线路页签，然后：

1. 填 **用户 ID** — 在控制台个人页面可以复制。
2. 填 **系统访问令牌** — 粘贴刚生成的那一枚。输入框默认隐藏内容，点右侧的眼睛图标可以查看。
3. 点「**绑定主站账户**」或「**绑定专线账户**」。

绑定成功后，顶部会显示这条线路的 **用户 ID、用户名、余额、用户分组和上次刷新时间**。绑定失败最常见的两个原因是用户 ID 抄错和令牌过期，界面会直接给出提示。

已经绑定过的线路有三个操作：

- **更新令牌** — 原有的系统访问令牌失效时，粘一枚新的换上去。
- **刷新** — 重新拉一次余额和令牌列表。
- **解绑** — 清掉这条线路的账户。**只影响当前选中的线路**，另一条线路不受影响。

绑定后账户信息保存在本机的 `echoflow-account.json`，不会上传。

## 选择令牌并配置渠道

账户绑好之后，区域下方会出现「**选择 API Key 并配置渠道**」。下拉框里列的是这个账户下的调用令牌，每一项显示**令牌名称和脱敏后的 Key 预览**，令牌的额度状态也在里面。

选中一枚令牌会打开统一的详细配置面板——模型、能力、高级参数都在那里设置。**只有点保存时，渠道才会真正出现在下方的模型渠道列表里。** 选错了直接关闭面板就行，不会留下半条记录。

账户下没有可用令牌时，先回控制台创建一枚，再点「刷新」。

## 令牌和 API Key 的区别

这是最容易混的一处，值得单独说清：

- **系统访问令牌** — 属于账户，用来证明"这个账户是你"。检测账号、读取令牌列表、后续换令牌都靠它。
- **调用令牌（API Key）** — 属于某个具体渠道，真正发出去做模型调用的凭据。

**桌面端不会接触完整的 API Key。** 你选的只是一枚令牌的 ID，测试、创建、更新这些动作都由服务端按「账户 + 令牌 ID」完成，并且强制走该令牌所属的端点。所以：

- 令牌列表里看到的永远是脱敏预览，完整 Key 不下发到桌面端。
- 给渠道换令牌不需要重新粘贴密钥，换一枚令牌 ID 即可。
- 主站账户的令牌只能建主站渠道，不会串到专线上去。

## 从旧版本升级

旧版本只支持单账户存储，升级后会自动迁移成主站 / 专线两个槽位：原来的账户落在**主站**，专线留空。

如果升级后账户区域看起来是空的，先点一次「刷新」；仍然空的话，说明迁移没有读到旧文件，重新绑定一次即可。旧文件 `qingyun-account.json` 只用于迁移读取，新数据一律写进 `echoflow-account.json`。

## 常见问题

**绑定后余额没显示。** 点「刷新」。账户刚绑定时余额可能还没同步，界面会显示「尚未同步」。

**提示令牌无效或已过期。** 回控制台重新生成一枚系统访问令牌，用「更新令牌」换上。

**下拉框里没有令牌。** 这个账户下还没建过调用令牌。默认情况下控制台会提供一枚，没有就自己建一个，然后点「刷新」。

**想改用第三方服务商。** 官方账户和第三方服务商可以并存，在模型渠道列表里随时切换，互不影响。具体见 [连接模型服务](./models.md)。
