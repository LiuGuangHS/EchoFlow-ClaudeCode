# 登录 EchoFlow SiHub

EchoFlow SiHub 是 EchoFlow 的推荐接入服务。登录之后，你不需要自己申请各家厂商的密钥，选一个调用令牌就能建好一条模型渠道。

如果你用的是别的服务商，看 [连接模型服务](./models.md)。这一页只讲 EchoFlow SiHub。

> 模型与服务仅在您所在地区法律法规允许的范围内提供，请自行确认所在地的合规要求与可用性。

## 前置条件

- 在 [EchoFlow 控制台](https://api.echoflowai.cc/console/personal) 注册过账号，并且账户里有余额
- 桌面端已经装好，见 [下载与安装](./install.md)

使用桌面端的站点登录时，无需提前生成系统访问令牌：登录窗口会直接把你已经登录的站点会话交给桌面端。

## 两条线路：主站与专线

EchoFlow SiHub 有两个入口，账户区域顶部是它们的切换页签：

| 线路 | 地址 | 什么时候选它 |
|---|---|---|
| **主站** | `https://api.echoflowai.cc` | 默认。多数情况下用这条 |
| **专线** | `https://expapi.echoflowai.cc` | 主站不稳或延迟偏高时换这条试试 |

**两条线路各自独立登录，凭据互不覆盖。** 你可以在主站登录一个账号、专线上登录另一个，再分别建渠道。页签上的小圆点是登录状态：绿色表示这条线路已经登录。

## 登录账户

在「设置 → 模型配置」里找到 EchoFlow SiHub 区域，选好线路页签，然后点「**登录 EchoFlow SiHub**」。在设置面板内完成站点登录。如果选择第三方登录，可能还会打开授权窗口。成功后会返回所选线路的账户面板。要离开登录页，可点「取消」或按 Esc。

登录成功后，顶部会显示这条线路的 **用户 ID、用户名、余额和上次刷新时间**。

已登录线路的常用操作：

- **刷新** — 重新拉一次余额和令牌列表。凭据失效时界面会提示重新登录。
- **登录 EchoFlow SiHub** — 桌面端重启时会尝试恢复登录。只有在提示凭据过期或无法恢复时，才需要重新登录。
- **解绑** — 清除桌面端当前线路的账户及站点登录状态。已在网关签发的调用令牌需要到控制台单独撤销。**只影响当前选中的线路**，另一条线路不受影响。

### 手动绑定（高级）

在本机使用桌面端时，也可以展开「**手动绑定（高级）**」，填 **用户 ID** 和**系统访问令牌**：

1. 用户 ID 在控制台个人页面可以复制。
2. 系统访问令牌在控制台的「安全设置 → 系统访问令牌 → 生成令牌」里生成。输入框默认隐藏内容，点右侧的眼睛图标可以查看。

远程浏览器连接只允许读取账户信息。需要绑定或更新凭据时，请在桌面端操作。

`echoflow-account.json` 保存线路、用户 ID，以及已同步的用户名、余额、令牌列表和刷新时间。手动绑定会把系统访问令牌写入此文件；已获取的完整调用密钥也可能以明文保存在其中。站点登录使用的 Cookie 或专线访问令牌由内存和该线路的浏览器存储管理，不写入账户文件。请把账户文件及迁移生成的 `.bak-before-migration-*` 备份当作凭据保管，不要附到诊断报告中。

## 选择令牌并配置渠道

账户登录之后，区域下方会列出这个账户下的调用令牌，每一项显示**令牌名称和脱敏后的 Key 预览**，令牌的额度状态也在里面。

选中一枚令牌会打开统一的详细配置面板——模型、能力、高级参数都在那里设置。**只有点保存时，渠道才会真正出现在下方的模型渠道列表里。** 选错了直接关闭面板就行，不会留下半条记录。

账户下没有可用令牌时，点列表上方的「**创建令牌**」，桌面端会向当前线路的网关申请令牌。创建结果不明确时，先到控制台核对令牌列表，避免重复创建。要改额度、改过期时间或看用量，点旁边的「**控制台**」到站点后台处理。

## 令牌和 API Key 的区别

这是最容易混的一处，值得单独说清：

- **系统访问令牌** — 属于账户，用来证明“这个账户是你”。手动绑定后，桌面端用它查询账户和令牌列表。
- **调用令牌（API Key）** — 属于某个具体渠道，真正发出去做模型调用的凭据。

**桌面端默认只显示脱敏的 API Key 预览。** 你选择的是令牌 ID，测试、创建、更新这些动作都由服务端按「账户 + 令牌 ID」完成，并且强制走该令牌所属的端点。从账户列表选择令牌即可，无需显示或复制完整密钥。
- 给渠道换令牌不需要重新粘贴密钥，换一枚令牌 ID 即可。
- 主站账户的令牌只能建主站渠道，不会串到专线上去。

## 从旧版本升级

升级时，旧版 `echoflow-account.json` 中的单个账户会迁入相应线路；没有线路标记的记录默认属于主站。

只有旧版 `qingyun-account.json` 时，原文件会保留，账户不会自动导入。请在需要的线路重新登录或手动绑定。

## 常见问题

**登录页关闭了，但账户没出现。** 取消时，已提交的登录仍可能完成。如果提示结果无法确认，先等面板重新读取所选线路的账户，再核对用户 ID。确认仍未绑定所需账户后再登录。

**登录后余额没显示。** 点「刷新」。账户刚登录时余额可能还没同步，界面会显示「尚未同步」。

**提示登录状态已失效。** 点「登录 EchoFlow SiHub」重新登录；用手动绑定的话，回控制台重新生成一枚系统访问令牌，用「更新令牌」换上。

**令牌列表里没有令牌。** 这个账户下还没建过调用令牌。点列表上方的「创建令牌」新建一枚，建好会直接出现在列表里，不需要刷新。

**想改用第三方服务商。** EchoFlow SiHub 和第三方服务商可以并存，在模型渠道列表里随时切换，互不影响。具体见 [连接模型服务](./models.md)。
