# Deep link protocol

This page is for anyone integrating with or debugging config-sharing links: what a link looks like, what it carries, and what gets checked on import. If you only want to share or import a config, [Config sharing](./config-sharing.md) is enough.

## URL structure

```text
echoflowcode://config/import?v=1&data=<url-safe-deflate-base64>
```

| Segment | Meaning |
|---|---|
| `echoflowcode` | The custom URL scheme the desktop app registers |
| `config/import` | The action: import a config bundle (may hold several providers) |
| `v` | Payload version, currently `1` |
| `data` | DEFLATE-compressed then URL-safe Base64 encoded payload — **not** plaintext JSON |

The `data` segment is generated by compressing the actual provider data, so every link differs.

The shape resembles `aionui://provider/add?...`, but this is a different app and a different protocol with a different payload — it is not AionUI's `{aionuiConfig}`.

## Payload v1

After decompression, the JSON is:

```typescript
{
  version: 1,
  source: 'team-admin',
  timestamp: 1234567890000,
  config: {
    providers: [{
      presetId: 'deepseek',
      name: 'DeepSeek (Team)',
      baseUrl: 'https://api.deepseek.com',
      apiFormat: 'openai_chat',
      authStrategy: 'api_key',
      models: {
        main: 'deepseek-chat',
        haiku: 'deepseek-chat',
        sonnet: 'deepseek-chat',
        opus: 'deepseek-chat',
      },
    }],
  },
}
```

| Field | Meaning |
|---|---|
| `version` | Fixed at `1` |
| `source` | Author-supplied label, used only in the import preview |
| `timestamp` | Generation time in milliseconds |
| `config.providers` | Array of providers with connection parameters and model mappings |

**The payload carries no API keys, access tokens, or machine identifiers.** That is a deliberate boundary, not an accident of the current format.

## Validation rules

The import side checks each of these and rejects the link if any fails:

1. Version must be `1`;
2. Timestamp must be within the validity window;
3. Required provider fields must all be present;
4. The endpoint protocol must be supported;
5. No sensitive field may be smuggled in.

| Item | Value |
|---|---|
| Validity | **30 days** from `timestamp` |
| Clock skew tolerated | up to **5 minutes** |

Badly drifted clocks cause validation to fail — if two machines disagree on the time, fix the system clock first.

## Safety boundaries

:::warning
Links are **not signed**. Both `source` and `timestamp` are supplied by whoever created the link, so a link **cannot prove its author's identity** — it does not authenticate that the config really came from your team's admin. Only import links from sources you trust.
:::

There is one more guard on the import side: **a provider with the same name and base URL is skipped**, so existing local configuration is never overwritten. Import is additive, and API keys are always left blank for the recipient to fill in.
